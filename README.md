# ctOWAS: cell-type-level omics-wide association studies

`ctOWAS` is an R package for **cell-type-level OWAS**. Bulk-tissue molecular
traits (such as gene expression or protein abundance) are modelled as a mixture
of K cell types, so genetic prediction weights can be estimated separately for
each cell type. These cell-type-specific weights are then combined with GWAS
summary statistics and an LD reference panel to test which cell type(s) carry a
molecule–trait association.

The repository contains:

| Folder | Contents |
|---|---|
| [`R/`](R) | Package source code |
| [`man/`](man) | Function documentation (generated by roxygen2) |
| [`data/`](data) | Small toy datasets for the examples below |
| [`Analysis_code/`](Analysis_code) | Scripts that reproduce the analyses and figures in the paper (not part of the package build) |
| [`result/`](result) | Supplementary tables (e.g. Table S1) |

---

## Main functions

| Step | Function | Purpose |
|---|---|---|
| 1. Cell-type fractions | `estimate_prior()` | Convert xCell enrichment scores into prior cell-type proportions with target means and bounds |
| | `pi_estimation_K()` | Refine prior proportions using bulk expression and marker genes, by repeated subsampling and averaging |
| | `deNet_composition_K_once()` | One run of the K-component EM refinement (called by `pi_estimation_K()`) |
| 2. Train weights | `ctOWAS_train_K()` | Train a cell-type-specific elastic-net prediction model for one gene or protein, with split-sample stability screening |
| 3. Association test | `ctOWAS_assoc_test_K()` | Test association using cell-type-specific weights, GWAS z-scores and an LD reference panel |
| Utilities | `run_gwas()` | Fast single-SNP GWAS (Gaussian, or binomial with a score test or GLM) |

See `?function_name` for full argument and output descriptions after
installation.

## Installation

`ctOWAS` requires R ≥ 4.1. Install the dependencies first:

```r
install.packages(c("remotes", "glmnet", "matrixStats"))

# ACAT: aggregated Cauchy association test (GitHub only)
remotes::install_github("yaowuliu/ACAT")
```

`matrixStats` is optional; it speeds up column variance calculations in
`ctOWAS_assoc_test_K()`.

Then install `ctOWAS` from this repository:

```r
remotes::install_github("songxiaoyu/ctOWAS")
library(ctOWAS)
```

### Step 1. Estimate cell-type fractions

Cell-type fractions are estimated in two stages.

**(a) Prior proportions.** `estimate_prior()` converts xCell enrichment scores
(xCell cell types × samples) into prior proportions whose column means match
user-supplied target proportions, within lower and upper bounds. Several xCell
types can be pooled into one compartment; their scores are averaged.

```r
library(ctOWAS)
data(xCellScore_example)

prior <- estimate_prior(
  xCellScore = xCellScore_example,   # xCell cell types x samples
  cell_types = list(
    CellType1 = "Cell1",
    CellType2 = "Cell2"
  ),
  mu    = c(0.4, 0.6),   # target mean proportions (sum to 1)
  lower = 0.01,
  upper = 0.99
)

head(prior)       # samples x cell types; rows sum to 1
colMeans(prior)   # equal to mu
```

In real data, run xCell or xCell2 (e.g. `xCell::xCellAnalysis()`) on your bulk 
expression to get the scores, and
set `mu` from external estimates of average tissue composition. 

**(b) Refined proportions.** `pi_estimation_K()` refines the prior using bulk
expression and marker genes. In each iteration it draws a random subset of
samples and runs a K-component EM model on the marker genes; the estimates are
then combined with a trimmed mean. The column names of `prior` must match the
names of `marker_list`.

```r
data(exprB_example, markers_example)

pi_hat <- pi_estimation_K(
  expr        = exprB_example,    # genes x samples
  n_iteration = 20,               # number of subsampling iterations
  prior       = prior,            # samples x cell types, from step (a)
  marker_list = markers_example,  # named list, few elements per cell type
  seed        = 1,
  verbose     = FALSE             # passed to deNet_composition_K_once()
)

head(pi_hat)      # samples x cell types; rows sum to 1
```

Other arguments of `deNet_composition_K_once()`, such as `prior_strength`
(how strongly estimates are shrunk toward the prior, default `10`), can also be
passed through `pi_estimation_K()`. The steps below use the pre-computed
fractions in `pi_k` (columns `Cell1`, `Cell2`).

### Step 1. Train a cell-type-specific prediction model

```r
data(x_example, y_example, pi_k)

fit <- ctOWAS_train_K(
  y     = y_example,   # molecular trait for one gene/protein (length N)
  x     = x_example,   # N x P cis-SNP dosage matrix
  pi_k  = pi_k,        # N x K cell-type fractions
  cov   = NULL,        # optional N x Q covariate matrix (with column names)
  yName = "Gene_A",
  alpha = 0.5,         # elastic-net mixing parameter
  seed  = 1
)

fit$W              # P x K matrix of cell-type-specific SNP weights
fit$intercept      # cell-type-specific intercepts
fit$Num_SNP_model  # number of SNPs with a non-zero weight in any cell type
```

The function first runs 11 random split-sample fits to give each predictor an
empirical FDR score, then uses those scores as penalty factors in the final
cross-validated elastic net, so stable predictors are penalised less.

With this toy dataset, `cv.glmnet` warns that there are fewer than three
observations per fold. You can ignore this warning for the example.

### Step 2. Test the association with GWAS summary statistics

```r
data(gwas_example)

gwas_z <- gwas_example$Beta / gwas_example$se_Beta

res <- ctOWAS_assoc_test_K(
  W              = fit$W,       # P x K weights (same SNP order as x_g)
  gwas_z_score   = gwas_z,      # GWAS z-scores for the P SNPs
  x_g            = x_example,   # LD reference genotypes (here: training data)
  n0             = 1000,        # GWAS controls
  n1             = 1000,        # GWAS cases
  family         = "binomial",  # or "gaussian" for a continuous trait
  regularization = "fixed",     # or "estimate"
  reg_scale      = 0.1
)

res$p_join_vec   # joint (correlation-adjusted) p-value for each cell type
res$p_join       # ACAT-combined p-value across cell types
res$p_sep        # separate (unadjusted) p-value for each cell type
res$mode         # "joint", "collinear_separate" or "invalid_variance_separate"
```

Expected output, approximately:

```text
$p_join_vec  0.143 0.427
$p_join      0.227
$p_sep       0.139 0.472
$mode        "joint"
```

For a continuous GWAS trait, use `family = "gaussian"` (`n0` and `n1` are then
not used). With `regularization = "estimate"`, the function chooses the
smallest regularization scale (between `reg_min_scale` and `reg_max_scale`)
that brings the condition number down to `condition_max`.

If any cell type has all-zero weights, or two predicted cell-type traits are
almost perfectly correlated, the joint adjustment is skipped and the separate
statistics are returned (`mode` tells you which case applies).

In a real analysis, `x_g` should be an ancestry-matched LD reference panel
(e.g. 1000 Genomes EUR). SNPs must be allele-harmonized and in the same order
in `W`, `gwas_z_score` and `x_g`.

### Optional: run a GWAS from individual-level data

If you have individual-level genotypes and phenotypes, `run_gwas()` produces
the z-scores needed in Step 3:

```r
set.seed(1)
pheno <- rnorm(nrow(x_example))
gwas  <- run_gwas(X = x_example, D = pheno, family0 = gaussian())
head(gwas)   # Beta, se_Beta, Z, P

# For case-control data (D coded 0/1):
# run_gwas(X, D, covar = covariates, family0 = binomial(), method_binomial = "score")
```

The score test (default for binomial traits) is much faster for many SNPs but
returns only `Z` and `P`; use `method_binomial = "glm"` if you also need effect
estimates.

## Analysis code for the paper

The scripts in [`Analysis_code/`](Analysis_code) reproduce the analyses in the
paper. Each folder matches one or more figures, and scripts are numbered in run
order. These scripts need large external datasets (GTEx, TCGA, DRIVE, HERMES
and 1000 Genomes) that are not included in this repository. Before running
them, edit the data paths at the top of each script.

| Figure | Folder | What it does |
|---|---|---|
| Figure 2 | [`Figure2_Simulation`](Analysis_code/Figure2_Simulation) | Simulations comparing ctOWAS, MiXcan and PrediXcan: genotype preparation, power, type I error (2,000 replicates) and plotting |
| Figure 3 | [`Figure3_GTEx_Breast_Prediction_Evaluation_DRIVE`](Analysis_code/Figure3_GTEx_Breast_Prediction_Evaluation_DRIVE) | Cleans GTEx breast data, estimates cell-type fractions, trains 2-cell-type models, evaluates prediction in TCGA and runs association analysis in DRIVE |
| Figure 4 | [`Figure4_3ct_Comparison`](Analysis_code/Figure4_3ct_Comparison) | Trains 3-cell-type breast models and compares them with the 2-cell-type models in DRIVE |
| Figures 5 and 6 (part 1) | [`Figure5_6.1_GTEx_Heart_Proteomics_Training_and_Evaluation`](Analysis_code/Figure5_6.1_GTEx_Heart_Proteomics_Training_and_Evaluation) | Processes and LD-prunes GTEx heart WGS genotypes, then trains cardiomyocyte vs. other-cell protein weights from GTEx heart proteomics |
| Figures 5 and 6 (part 2) | [`Figure5_6.2_PWAS_HERMES_BigHeart`](Analysis_code/Figure5_6.2_PWAS_HERMES_BigHeart) | Heart PWAS with HERMES DCM GWAS: liftover, weight export, data preparation, 1000 Genomes EUR LD reference, association and plotting |

[`Analysis_code/Archive/`](Analysis_code/Archive) holds earlier or exploratory
scripts that are not needed to reproduce the paper.

Example: run the heart PWAS workflow in order:

```bash
DIR=Analysis_code/Figure5_6.2_PWAS_HERMES_BigHeart
python  $DIR/6.1_liftover_hermes_gwas.py
Rscript $DIR/6.1b_export_heart_weights_for_hermes.R
Rscript $DIR/6.2_HERMES_prepare_data_pwas.R
bash    $DIR/6.3_1000Genome_keep_eur_plink_hermes_pwas.sh
Rscript $DIR/6.4_HERMES_run_analysis_pwas.R
Rscript $DIR/6.5_plot_hermes_pwas.R
```
